## 1. 时间分配

以 CSP-S / NOIP 的 **4 小时 4 题** 为例：

| 阶段 | 时长 | 任务 |
|---|---|---|
| 通读全部题目 | 10~15 min | 判断难度、想暴力 |
| 第 1 题 | 30~40 min | 必须拿满 |
| 第 2 题 | 40~50 min | 尽量拿满 |
| 第 3 题 | 50~60 min | 先暴力再优化 |
| 第 4 题 | 40~50 min | 暴力 + 部分分 |
| 检查 + 对拍 | 20~30 min | 静态检查、测样例 |

> **核心原则**：先保证会的题一分不丢，再去啃难题。**一题满分 > 四题暴力**。

---

## 2. 读题顺序

1. **先全部读一遍**，不要一上来就死磕第一题；
2. 标记每题：
   - ✅ 有明确思路
   - 🔶 有部分分思路
   - ❓ 完全不会
3. **从 ✅ 开始做**，再做 🔶，最后看 ❓；
4. 注意题目中的**数据范围表格**，它通常暗示了算法：
   - $n \le 10^5$ ⇒ $O(n \log n)$
   - $n \le 5000$ ⇒ $O(n^2)$
   - $n \le 20$ ⇒ 状压 DP
   - $n \le 10^9$ ⇒ 数学/二分
   - 有「特殊性质」⇒ 先拿特殊性质分

## 3. 暴力分策略

**部分分是竞赛的半壁江山。** 一个正确的暴力往往能拿 30~60 分。

### 3.1 常见部分分来源

| 数据档位 | 暴力思路 | 分值占比 |
|---|---|---|
| $n \le 10$ | 全排列 / 暴搜 | 20% |
| $n \le 100$ | $O(n^3)$ DP | 20% |
| 特殊性质 A | 针对性质写特解 | 20% |
| 特殊性质 B | 同上 | 20% |
| 满数据 | 正解 | 20% |

### 3.2 暴力写法要点

1. **先写最朴素的搜索**，确保正确；
2. 能加**记忆化**就加，往往能多过一档；
3. 能加**剪枝**就加；
4. 不要为了暴力写得太复杂，**正确 > 快**。

### 3.3 分档写法（重要技巧）

```cpp
if (n <= 10) {
    // 暴力
} else if (满足特殊性质A) {
    // 特解
} else {
    // 正解或次优解
}
```

一个文件里写多档，**按数据范围分支**，能最大化得分。

## 4. 正解思考流程

拿到一道有思路的题，按这个顺序想：

1. **题目要求什么？** 明确输入输出与目标函数；
2. **数据范围？** 反推复杂度；
3. **有没有经典模型？** 区间 → 线段树/前缀和；图 → 最短路/MST；序列 → DP/贪心；
4. **特殊性质提示什么？** 往往正解就是特殊性质的一般化；
5. **能不能先做小数据？** 从小数据找规律；
6. **换个角度？** 逆向思维、补集思想、离线处理、差分。

### 4.1 卡住时的破局方法

- **写暴力找规律**：$n=1,2,3,4$ 手算答案；
- **看样例解释**：官方解释里常藏提示；
- **题目名/文件名**：`crystal`、`subway` 等往往暗示模型；
- **放弃，去拿别的题的分**。

---

## 5. 代码实现纪律

1. **先在纸上写伪代码**，再敲键盘；
2. **模块化**：把读入、求解、输出分开；
3. **数组大小统一多开**：`N = 100005` 而不是 `100000`；
4. **变量命名清晰**：`n, m, ans, cnt` 而不是 `a, b, c, d`；
5. **写一段测一段**：不要一次写完 300 行再编译；
6. **每道题独立文件**，不要在一个文件里改来改去；
7. **提交前必跑样例**。

---

## 6. 最后 30 分钟

**不要再开新题。** 做三件事：

1. **静态检查所有已提交代码**：
   - 数组大小、`long long`、多组数据清空；
   - `freopen` 文件名正确；
   - 输出格式（行末空格、换行）；
2. **重跑所有样例**；
3. **提交所有能交的版本**（哪怕是暴力）。

> 很多人的分数是**最后 10 分钟**找回来的（比如 `freopen` 写错、数组开小）。

## 7. 常见心态问题

| 问题 | 应对 |
|---|---|
| 第一题卡住就慌 | 先跳过，做后面的，最后回来 |
| 想追求满分导致全崩 | 先拿暴力分，再优化 |
| 代码调不出来越调越乱 | 停手，重新读题，或对拍 |
| 看到别人提前交卷 | 与你无关，按自己节奏 |
| 最后 10 分钟发现大 bug | 冷静，能修就修，修不好交旧版 |

## 附：常见错误与练习清单

### 常见错误

1. **忽略边界情形**：空输入、最小规模、极大值、全相同元素。
2. **想当然地套模板**：没有先确认问题的前提条件是否满足。
3. **调试输出忘记删除**：提交前检索 `cerr`、`printf("debug` 等。
4. **变量作用域混乱**：局部变量遮蔽全局变量，多组数据不清空。
5. **时间估算错误**：只看复杂度，忽略常数与评测机性能。

### 练习建议

- 先用最小规模数据手算一遍，确认思路无误；
- 写完后用对拍脚本自测（见 [对拍](../对拍/README.md)）；
- 整理一份自己的错题本，定期回看；
- 把本文的方法固化成checklist，每次比赛前过一遍。
