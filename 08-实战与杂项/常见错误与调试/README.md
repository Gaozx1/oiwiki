## 1. 错误分类总览

| 缩写 | 含义 | 常见原因 |
|---|---|---|
| CE | Compile Error | 语法、头文件、类型 |
| RE | Runtime Error | 数组越界、除零、栈溢出、空指针 |
| WA | Wrong Answer | 逻辑错误、边界、溢出、精度 |
| TLE | Time Limit Exceeded | 复杂度、常数、死循环 |
| MLE | Memory Limit Exceeded | 数组开太大、递归太深 |

## 2. 编译错误（CE）

### 2.1 常见原因

1. **漏头文件**：用了 `vector` 没 `#include <vector>`，用了 `memset` 没 `#include <cstring>`；
2. **C++ 版本不符**：`auto`、结构化绑定需要 C++11/17；
3. **变量名拼写**：`lenght`、`nxt` 与 `next` 冲突（`next` 是 std 里的函数）；
4. **`long long` 与 `int` 混用导致的类型推导问题**；
5. **少分号、少括号**。

### 2.2 解决方法

本地编译时用**和评测机完全相同的命令**：

```bash
g++ -O2 -std=c++14 -static -Wall -Wextra a.cpp -o a
```

`-Wall -Wextra` 会报出大量警告，很多警告就是潜在 bug。

## 3. 运行错误（RE）

### 3.1 数组越界

最常见。典型场景：

```cpp
int a[100005];
for (int i = 1; i <= n; ++i) a[i] = ...;   // n 可能 = 100000，a[100000] 合法
```

检查点：

- 循环上界是 `<` 还是 `<=`；
- 下标从 0 还是从 1 开始；
- 数组大小是否比最大数据多开 5~10；
- 二维数组第二维是否够；
- 字符串长度 +1（`'\0'`）。

### 3.2 除零 / 模零

```cpp
int x = a / b;   // b 可能为 0
```

尤其在数论题里，`inv(0)` 会直接崩。

### 3.3 栈溢出

递归深度过大（> 10 万层）会爆栈。解决方法：

- 改迭代；
- 全局数组代替局部大数组（局部变量在栈上）；
- 增大栈空间（本地调试用，比赛无效）。

### 3.4 空指针 / 未初始化

```cpp
int *p; 
*p = 1;   // 未分配
```

### 3.5 迭代器失效

```cpp
for (auto it = s.begin(); it != s.end(); ) {
    if (bad(*it)) it = s.erase(it);   // erase 返回下一个迭代器
    else ++it;
}
```

在 `vector` 里 `push_back` 后原有迭代器可能全部失效。

## 4. 答案错误（WA）

### 4.1 溢出（最高频！）

```cpp
int a = 100000, b = 100000;
long long c = a * b;      // 错！先按 int 计算溢出，再赋值
long long d = 1LL * a * b; // 对
```

记住几个阈值：

| 类型 | 最大值 |
|---|---|
| `int` | $2.1 \times 10^9$ |
| `unsigned int` | $4.3 \times 10^9$ |
| `long long` | $9.2 \times 10^{18}$ |

**经验**：只要涉及「两个 $10^5$ 相乘」「路径长度累加」「计数」就要想 `long long`。

### 4.2 边界条件

- $n = 1$、$n = 0$、$m = 0$；
- 所有数相同；
- 负数（`-1 / 2 = 0` 而非 $-1$，向上取整要 `(a + b - 1) / b` 只对非负成立）；
- 空序列、只有一个点、树退化成链；
- 最大值、最小值、极值数据。

### 4.3 浮点精度

```cpp
const double EPS = 1e-9;
if (fabs(a - b) < EPS) { /* 相等 */ }
```

- 不要用 `==` 比较浮点数；
- 二分时固定迭代 100 次比 `while (r - l > eps)` 更稳；
- 大数相加再比较会放大误差。

### 4.4 初始化

- 多组数据忘清空数组/容器；
- DP 初值没设 `-INF` 或 `INF`；
- 并查集父数组没初始化为自己；
- 图论 $dist$ 数组没置 `INF`。

### 4.5 下标问题

- 差分数组大小要 `n + 2`；
- 线段树要开 `4n`；
- 树剖要开 `2n`；
- `string` 下标从 0 开始，题目从 1 开始时注意转换。

### 4.6 有向 / 无向

- 无向图加边要加两次；
- 树边加一次；
- 网络流反向边容量为 0。

### 4.7 多组数据

```cpp
while (t--) {
    // 每组要清空全局变量！
}
```

## 5. 超时（TLE）

1. **复杂度算错**：$O(n^2)$ 在 $n=10^5$ 必挂；
2. **常数过大**：见[卡常技巧](../卡常技巧/README.md)；
3. **死循环**：`while` 条件写反、BFS 忘记标记访问、二分 `l = mid` 死循环；
4. **STL 误用**：`map` 的 `operator[]` 每次 $O(\log n)$；`vector` 头部 `insert` 是 $O(n)$；
5. **频繁 `memset` 大数组**：多组数据时 $O(n)$ 清空也要算进复杂度。

---

## 6. 超内存（MLE）

| 数据结构 | 空间 |
|---|---|
| `int a[10^7]` | 40 MB |
| `long long a[10^7]` | 80 MB |
| `vector<vector<int>> g(10^5)` | 约 2.4 MB 仅空 vector 头 |
| 线段树 `4 * 10^6` 个 `long long` 节点 | 128 MB |

优化方法：

- 用 `int` 代替 `long long`（确认不溢出）；
- 用链式前向星代替 `vector<vector<int>>`；
- 滚动数组；
- `vector` 用 `shrink_to_fit()`。

## 7. 系统调试方法

### 7.1 打印调试

```cpp
#define debug(x) cerr << #x << " = " << (x) << endl
```

输出到 `stderr`，不会干扰 `stdout` 的答案。

### 7.2 分段注释法

把代码一块块注释掉，看哪块导致错误。适用于大程序。

### 7.3 对拍

见[对拍](../对拍/README.md)。**最有效的方法**。

### 7.4 二分缩小数据

如果长程序在某组大数据上错，把数据规模减半再测，直到最小复现。

### 7.5 静态检查清单

- [ ] 数组大小够不够（多开 5~10）
- [ ] 会不会溢出（乘法、加法、累加）
- [ ] 多组数据清空了吗
- [ ] 边界 $n=1$、$n=0$ 测过吗
- [ ] 递归深度会不会爆栈
- [ ] 输入输出文件名对吗（`freopen`）
- [ ] 有没有把 `int` 当 `long long` 用
- [ ] 循环下标从 0 还是 1
- [ ] 图是否双向加边
- [ ] 模运算是否有负数

## 8. 调试的哲学

1. **先怀疑最简单的**：变量名、下标、初始化，往往是最愚蠢的错误；
2. **一次只改一处**：同时改三处会让你不知道是哪处修好的；
3. **相信数据不信直觉**：打印中间结果；
4. **保留现场**：出错的数据、代码版本都备份；
5. **写代码时就想着怎么调试**：模块化、加断点、命名清晰。

## 附：万能调试模板

```cpp
#include <bits/stdc++.h>
using namespace std;

#ifdef LOCAL
#define debug(x) cerr << "[" << __LINE__ << "] " << #x << " = " << (x) << "\n"
#else
#define debug(x)
#endif

int main() {
#ifndef LOCAL
    freopen("xxx.in", "r", stdin);
    freopen("xxx.out", "w", stdout);
#endif
    // ...
    return 0;
}
```

本地编译时加 `-DLOCAL`，提交时不加，`debug` 自动失效。

## 附：常见错误与练习清单

### 常见错误

1. **忽略边界情形**：空输入、最小规模、极大值、全相同元素。
2. **想当然地套模板**：没有先确认问题的前提条件是否满足。
3. **调试输出忘记删除**：提交前检索 `cerr`、`printf("debug` 等。
4. **变量作用域混乱**：局部变量遮蔽全局变量，多组数据不清空。
5. **时间估算错误**：只看复杂度，忽略常数与评测机性能。

### 练习建议

- 先用最小规模数据手算一遍，确认思路无误；
- 写完后用对拍脚本自测（见 [对拍](../对拍/README.md)）；
- 整理一份自己的错题本，定期回看；
- 把本文的方法固化成checklist，每次比赛前过一遍。
