## 1. 为什么需要复杂度

假设有两个算法：

- 算法 A：$n^2$ 次操作；
- 算法 B：$n \log n$ 次操作。

当 $n = 1000$ 时，A 约 $10^6$ 次，B 约 $10^4$ 次，两者都能过。当 $n = 10^6$ 时，A 约 $10^{12}$ 次，需要跑几个小时；B 约 $2\times10^7$ 次，一秒钟内完成。

**复杂度分析就是让你在写代码之前就知道这件事。** 它忽略常数、只保留增长最快的项，因此与机器速度无关，是一种「跨平台」的性能描述。

### 一个直观的对比

```
 n = 10        n = 100        n = 1000
O(1)     1              1               1
O(log n) 3.3            6.6             10
O(n)     10             100             1000
O(n^2)   100            10000           1000000
O(2^n)   1024           1.3e30          1e301
```

## 2. 大 O 记号

### 2.1 定义

设 $f(n)$、$g(n)$ 是定义在正整数上的函数。若存在正常数 $c$ 和 $n_0$，使得当 $n \ge n_0$ 时恒有

$$0 \le f(n) \le c \cdot g(n)$$

则称 $f(n) = O(g(n))$，即 $f$ 的增长**不超过** $g$ 的常数倍。

直观理解：**$O(\cdot)$ 是「上界」，忽略常数因子和低阶项**。

### 2.2 例子

- $3n^2 + 5n + 7 = O(n^2)$：最高次项决定增长；
- $2n + 100 = O(n)$：常数 100 在 $n$ 很大时可忽略；
- $n^3 + n^2 = O(n^3)$；
- $\log_2 n$ 与 $\log_{10} n$ 只差常数倍，统一写 $O(\log n)$。

### 2.3 其他记号

| 记号 | 含义 | 直观 |
|---|---|---|
| $O(g)$ | 上界 | $f$ 增长不快于 $g$ |
| $\Omega(g)$ | 下界 | $f$ 增长不慢于 $g$ |
| $\Theta(g)$ | 紧界 | $f$ 与 $g$ 同阶 |
| $o(g)$ | 严格上界 | $f/g \to 0$ |

OI 中 95% 的场合用 $O$ 就够了。

## 3. 常见复杂度阶

从快到慢：

$$O(1) < O(\log n) < O(\sqrt{n}) < O(n) < O(n\log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)$$

| 阶 | 名称 | 典型算法 |
|---|---|---|
| $O(1)$ | 常数 | 数组下标访问、哈希查找 |
| $O(\log n)$ | 对数 | 二分查找、平衡树操作 |
| $O(\sqrt{n})$ | 根号 | 试除法判素、分块 |
| $O(n)$ | 线性 | 遍历、前缀和 |
| $O(n\log n)$ | 线性对数 | 归并排序、`std::sort`、堆排序 |
| $O(n^2)$ | 平方 | 冒泡/选择/插入排序、朴素 DP |
| $O(n^3)$ | 立方 | Floyd、矩阵乘法（朴素） |
| $O(2^n)$ | 指数 | 子集枚举、朴素搜索 |
| $O(n!)$ | 阶乘 | 全排列枚举 |

### 增长速度的直觉

$$n = 10^5 \text{ 时：}\quad \log n \approx 17,\quad n\log n \approx 1.7\times10^6,\quad n^2 = 10^{10}$$

所以 $O(n^2)$ 在 $n = 10^5$ 时必然超时，而 $O(n\log n)$ 轻松通过。

## 4. 时间复杂度分析方法

### 4.1 数循环

**单层循环**：

```cpp
for (int i = 0; i < n; ++i) { ... }      // O(n)
```

**双层嵌套**：

```cpp
for (int i = 0; i < n; ++i)
    for (int j = 0; j < n; ++j)
        ...;                              // O(n^2)
```

**内层依赖外层**：

```cpp
for (int i = 0; i < n; ++i)
    for (int j = i; j < n; ++j)
        ...;                              // 总次数 n + (n-1) + ... + 1 = n(n+1)/2 = O(n^2)
```

**步长不是 1**：

```cpp
for (int i = 1; i <= n; i *= 2) { ... }   // O(log n)
```

### 4.2 并列取最大，嵌套取乘积

```cpp
for (int i = 0; i < n; ++i) { ... }       // O(n)
for (int i = 0; i < n; ++i)               // O(n^2)
    for (int j = 0; j < n; ++j) { ... }
// 总复杂度 O(n) + O(n^2) = O(n^2)
```

### 4.3 递归的分析

```cpp
int f(int n) {
    if (n <= 1) return 1;
    return f(n - 1) + f(n - 2);   // 斐波那契朴素递归
}
```

递归树每层分两叉，深度 $n$，节点数约 $2^n$，所以复杂度 $O(2^n)$。

而：

```cpp
int g(int n) {
    if (n <= 1) return 1;
    return g(n / 2) + 1;          // 每次规模减半
}
```

递归深度 $\log_2 n$，复杂度 $O(\log n)$。

### 4.4 常见陷阱

- **`std::sort` 是 $O(n\log n)$**，不是 $O(n)$；
- **`map` 的每次操作是 $O(\log n)$**，遍历整个 `map` 是 $O(n\log n)$；
- **`string` 的 `substr` 是 $O(\text{长度})$**，在循环里反复调用可能变成 $O(n^2)$；
- **`vector::insert` 中间插入是 $O(n)$**。

## 5. 空间复杂度

空间复杂度衡量算法额外占用的内存随 $n$ 的增长速度。

```cpp
int a[100005];              // O(n)
int g[1005][1005];          // O(n^2)，n = 1000 时约 4 MB
vector<int> v(n);           // O(n)
```

### 5.1 常见空间限制与估算

| 限制 | 可用的 `int` 数量（约） |
|---|---|
| 16 MB | $4\times10^6$ |
| 64 MB | $1.6\times10^7$ |
| 128 MB | $3.2\times10^7$ |
| 256 MB | $6.4\times10^7$ |
| 512 MB | $1.28\times10^8$ |

计算方式：`int` 占 4 字节，$128\text{ MB} = 128 \times 1024 \times 1024$ 字节 $\approx 1.34\times10^8$ 字节，除以 4 得 $3.35\times10^7$ 个 `int`。

### 5.2 空间换时间

很多优化本质是用空间换时间：

- **前缀和**：$O(n)$ 空间换 $O(1)$ 区间查询；
- **记忆化搜索**：$O(\text{状态数})$ 空间换掉重复计算；
- **离散化**：把大值域压缩到 $O(n)$ 空间。

## 6. 均摊分析

有些操作**单次可能很慢，但一串操作的平均代价很小**。

### 6.1 `vector::push_back`

`vector` 扩容时要把所有元素搬到新内存，单次 $O(n)$。但扩容后容量翻倍，接下来 $n$ 次插入都不会再扩容。把扩容代价摊到每次插入上：

$$\frac{1 + 2 + 4 + \cdots + n}{n} = \frac{2n - 1}{n} < 2 = O(1)$$

所以 `push_back` 的**均摊**复杂度是 $O(1)$。

### 6.2 单调栈

每个元素最多进栈一次、出栈一次，所以 $n$ 次操作总共 $O(n)$，均摊每次 $O(1)$。

### 6.3 并查集的路径压缩

单次 `find` 可能走很长的链，但路径压缩后树的深度迅速降低，均摊接近 $O(1)$（严格是 $O(\alpha(n))$，其中 $\alpha$ 是反阿克曼函数，增长极慢）。

## 7. 主定理与递归复杂度

对于形如

$$T(n) = aT\left(\frac{n}{b}\right) + f(n)$$

的递归式（$a \ge 1$，$b > 1$），比较 $f(n)$ 与 $n^{\log_b a}$：

1. 若 $f(n) = O(n^{\log_b a - \epsilon})$，则 $T(n) = \Theta(n^{\log_b a})$；
2. 若 $f(n) = \Theta(n^{\log_b a})$，则 $T(n) = \Theta(n^{\log_b a}\log n)$；
3. 若 $f(n) = \Omega(n^{\log_b a + \epsilon})$，则 $T(n) = \Theta(f(n))$。

### 常见例子

| 递归式 | 复杂度 | 对应算法 |
|---|---|---|
| $T(n) = 2T(n/2) + O(n)$ | $O(n\log n)$ | 归并排序 |
| $T(n) = 2T(n/2) + O(1)$ | $O(n)$ | 线段树建树 |
| $T(n) = T(n/2) + O(1)$ | $O(\log n)$ | 二分查找 |
| $T(n) = 2T(n-1) + O(1)$ | $O(2^n)$ | 汉诺塔 |

> 主定理不是万能的，遇到 $T(n) = T(n-1) + O(n)$ 这类要直接展开：$n + (n-1) + \cdots = O(n^2)$。

## 8. 数据规模与算法选择

经验法则（假设 1 秒约 $10^8$ 次简单操作）：

| $n$ 的范围 | 可接受的复杂度 |
|---|---|
| $n \le 10$ | $O(n!)$、$O(2^n)$ |
| $n \le 20$ | $O(2^n)$ |
| $n \le 100$ | $O(n^3)$ |
| $n \le 1000$ | $O(n^2)$ |
| $n \le 10^5$ | $O(n\log n)$ |
| $n \le 10^6$ | $O(n)$ 或 $O(n\log n)$ 常数小 |
| $n \le 10^8$ | $O(n)$ 常数极小 |

### 读题第一步：看数据范围

拿到题目先看 $n$ 的上限，反推需要的复杂度：

- $n \le 20$ → 状压 DP / 暴力搜索；
- $n \le 5000$ → $O(n^2)$ DP；
- $n \le 10^5$ → 排序、二分、树状数组、线段树；
- $n \le 10^6$ → 线性扫描、前缀和。

## 9. 模板代码：复杂度实测

下面的程序用计时器实测不同复杂度在 $n = 10^5$ 时的耗时，帮助建立直觉：

```cpp
#include <bits/stdc++.h>
using namespace std;
using namespace std::chrono;

int main() {
    const int n = 100000;

    auto t1 = high_resolution_clock::now();          // O(n)：一次线性扫描
    long long s1 = 0;
    for (int i = 0; i < n; ++i) s1 += i;
    auto t2 = high_resolution_clock::now();
    cout << "O(n): " << duration_cast<microseconds>(t2 - t1).count() << " us\n";

    vector<int> v(n);
    for (int i = 0; i < n; ++i) v[i] = rand();
    auto t3 = high_resolution_clock::now();          // O(n log n)：排序
    sort(v.begin(), v.end());
    auto t4 = high_resolution_clock::now();
    cout << "O(nlogn): " << duration_cast<microseconds>(t4 - t3).count() << " us\n";

    const int m = n / 100;                           // O(n^2)：只跑 1/100 规模
    auto t5 = high_resolution_clock::now();
    long long s2 = 0;
    for (int i = 0; i < m; ++i)
        for (int j = 0; j < m; ++j) s2 += i ^ j;
    auto t6 = high_resolution_clock::now();
    cout << "O(n^2) [n/100]: " << duration_cast<microseconds>(t6 - t5).count() << " us\n";

    cout << s1 << ' ' << s2 << '\n';
    return 0;
}
```

> 比赛时不要用 `clock()` 做「优化判断」，因为评测机速度与本地不同。复杂度分析才是可靠依据。

## 10. 经典例题

### 例题 1：判断复杂度

**题意**：下面这段代码的复杂度是多少？

```cpp
int sum = 0;
for (int i = 1; i <= n; i *= 2)
    for (int j = 0; j < n; ++j)
        ++sum;
```

**思路**：外层 `i` 按 $1, 2, 4, \ldots$ 增长，共执行 $\lfloor \log_2 n \rfloor + 1$ 次；内层固定执行 $n$ 次。总次数 $n(\log_2 n + 1) = O(n\log n)$。

**复杂度**：$O(n\log n)$。

### 例题 2：分析递归

**题意**：求 `f(n)` 的时间复杂度：

```cpp
int f(int n) {
    if (n <= 1) return 1;
    return f(n / 2) + f(n / 2);
}
```

**思路**：每层把问题分成两个规模减半的子问题，共 $\log_2 n$ 层，第 $k$ 层有 $2^k$ 个节点，每层总工作量是 $2^k$。总工作量

$$1 + 2 + 4 + \cdots + 2^{\log_2 n} = 2n - 1 = O(n)$$

（这是主定理第二种情形：$a = 2$，$b = 2$，$f(n) = O(1)$，$n^{\log_b a} = n$，所以 $T(n) = \Theta(n)$。）

**复杂度**：$O(n)$。

### 例题 3：空间估算

**题意**：程序开了 `int a[5005][5005]` 和 `long long b[1000005]`，在 128 MB 内存限制下能过吗？

**思路**：

- `a`：$5005 \times 5005 \times 4$ 字节 $\approx 100.2$ MB；
- `b`：$10^6 \times 8$ 字节 $= 8$ MB；
- 合计约 $108$ MB $< 128$ MB，勉强能过，但几乎没有余量。

**结论**：能过，但应尽量把 `a` 的类型改小（如 `short`）或换成一维数组。

### 例题 4：选择算法

**题意**：给定 $n \le 10^5$ 个整数，求区间 $[l, r]$ 的和，共 $q \le 10^5$ 次询问。

**思路**：

- 朴素做法：每次循环求和，单次 $O(n)$，总 $O(nq) = 10^{10}$，超时；
- 前缀和：预处理 $O(n)$，每次询问 $O(1)$，总 $O(n + q)$，通过。

**复杂度**：$O(n + q)$。

```cpp
int main() {
    int n, q;
    cin >> n >> q;
    vector<long long> pre(n + 1, 0);
    for (int i = 1; i <= n; ++i) {
        int x;
        cin >> x;
        pre[i] = pre[i - 1] + x;
    }
    while (q--) {
        int l, r;
        cin >> l >> r;
        cout << pre[r] - pre[l - 1] << '\n';
    }
    return 0;
}
```

## 11. 易错点

1. **只看最坏情况**：复杂度分析通常讨论最坏情况，但哈希表要区分平均与最坏。
2. **忽略常数**：$O(n)$ 的算法常数可能是 $100$，$O(n\log n)$ 的常数可能是 $1$，小数据下后者可能更快。3. **循环条件里的隐藏开销**：`for (int i = 0; i < s.size(); ++i)` 中 `s.size()` 是 $O(1)$，但 `strlen(s)` 是 $O(n)$。
4. **误判 `std::sort` 为 $O(n)$**：它是 $O(n\log n)$。
5. **递归复杂度算错**：不要只看递归深度，要看每层的工作量。
6. **空间复杂度漏算**：递归栈、临时 `vector`、字符串拼接都占空间。
7. **`vector` 的 `push_back` 不是严格 $O(1)$**：均摊是，但单次可能 $O(n)$。
8. **`map` 遍历是 $O(n\log n)$**：不是 $O(n)$。
9. **$n$ 与值域混淆**：离散化后值域是 $n$，但原值可能到 $10^9$。
10. **忽略输入输出耗时**：$10^7$ 个整数用未加速 `cin` 可能直接 TLE。

## 12. 练习建议

### 12.1 学习路线（由易到难）

1. **数循环**：给一段代码，写出它的复杂度。
2. **比较阶**：判断 $n\log n$ 与 $n^{1.5}$ 谁增长快。
3. **递归分析**：用递归树分析归并排序、二分查找。
4. **空间估算**：给定数组大小与内存限制，判断是否超限。
5. **算法选择**：根据数据范围反推算法。
6. **均摊分析**：分析 `vector`、单调栈、并查集。

### 12.2 刷题清单

| 难度 | 题目 | 训练点 |
|---|---|---|
| 入门 | 洛谷 P1001 A+B Problem | 认识 $O(1)$ |
| 入门 | 洛谷 P1177 快速排序 | $O(n\log n)$ 排序 |
| 普及− | 洛谷 P2249 查找 | 二分 $O(\log n)$ |
| 普及− | 洛谷 P1115 最大子段和 | $O(n)$ vs $O(n^2)$ |
| 普及/提高− | 洛谷 P3374 树状数组 1 | $O(\log n)$ 单点修改 |
| 普及/提高− | 洛谷 P1908 逆序对 | $O(n\log n)$ 分治 |

### 12.3 学习检查清单

- [ ] 能写出大 O 的定义
- [ ] 能排出常见复杂度阶的大小顺序
- [ ] 能数出多重循环的复杂度
- [ ] 能用递归树分析简单递归
- [ ] 能根据 $n$ 的范围选择算法
- [ ] 能估算数组占用的内存
- [ ] 理解均摊复杂度的含义

> **核心思想**：复杂度分析是「用数学代替试错」。**写代码前先算一遍复杂度**，比提交十次看结果要高效得多。
